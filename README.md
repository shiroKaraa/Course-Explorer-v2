# Course Data Manager (Course Explorer v2)

Aplikasi manajemen data course yang dibangun sebagai mini project Praktikum Pemrograman Mobile Pertemuan 7. Aplikasi ini merupakan pengembangan dari Course Explorer v2 (Pertemuan 6) yang mengintegrasikan Flutter dengan REST API dan backend database (Supabase).

## Fitur Utama

- ✅ **CRUD Lengkap:** Read (SELECT), Create (INSERT), Update (PUT), Delete (DELETE) ke database PostgreSQL (Supabase).
- ✅ **State Management:** Loading, Success, Empty, dan Error State dengan tombol Retry.
- ✅ **Favorites:** State global yang konsisten di Home, Courses, dan Profile (menggunakan `code` sebagai kunci).
- ✅ **Responsif:** NavigationBar di layar kecil, NavigationRail di layar >= 840px. Grid menyesuaikan jumlah kolom.
- ✅ **Pencarian & Filter:** Berdasarkan judul, kode, dan status.
- ✅ **Validasi & Keamanan:** Form validation, konfirmasi delete, anti double-submit, dan RLS Supabase.

---

## Arsitektur

Aplikasi ini menerapkan *Layered Architecture* dan *Repository Pattern* (Dependency Inversion) agar sumber data (REST API ↔ Supabase) dapat diganti hanya dengan mengubah satu baris di `main.dart`.

```text
UI (Screens/Widgets)
   ↓ context.watch/read
Provider (CourseProvider — ChangeNotifier)
   ↓
Repository (CourseRepository)
   ↓
Data Source (CourseSupabaseService / CourseApiService)
   ↓
Supabase (PostgreSQL) / REST API Dummy
```

## Cara Menjalankan

1.  **Clone repository** ini.
2.  **Buat Project Supabase** dan buat tabel `courses` (lihat schema di bawah).
3.  **Buat file `.env`** di root project dan isi dengan kredensial Supabase Anda (jangan gunakan `service_role` key):
    ```env

    SUPABASE_ANON_KEY=eyJhbGci...
    ```
4.  Jalankan `flutter pub get`.
5.  Jalankan `flutter run`.

## Schema Database (Supabase)

```sql
create table courses (
  id bigint generated by default as identity primary key,
  code text not null unique,
  title text not null,
  credits int not null default 2,
  status text not null default 'planned',
  description text default '',
  dosen text default '-',
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);

-- RLS
alter table courses enable row level security;

-- Policies (untuk anon key)
create policy "Enable read access for all users" on courses for select using (true);
create policy "Enable insert for all users" on courses for insert with check (true);
create policy "Enable update for all users" on courses for update using (true) with check (true);
create policy "Enable delete for all users" on courses for delete using (true);
```

## Catatan Perjalanan Praktikum (Tahap 0 - 18)

Berikut adalah ringkasan temuan dan pembelajaran di setiap tahap:

### Tahap 0 — Persiapan Project
Project Course Explorer v2 dari Pertemuan 6 berhasil dijalankan tanpa error. Package `http` ditambahkan dan di-resolve pada `pubspec.lock`. Struktur folder W6 terverifikasi utuh. Git remote origin mengarah ke repository yang benar. Nama dan NIM tampil di Home dan Profile.

### Tahap 1 — REST Fundamentals
Menggunakan JSONPlaceholder sebagai API latihan. Endpoint `GET /posts` mengembalikan `200 OK` dengan format JSON array. Ditemukan 4 field utama: `userId`, `id`, `title`, dan `body`. URL API dipusatkan di `AppConfig` dan didokumentasikan.

### Tahap 2 — HTTP GET
Membuat `CourseApiService` yang menggunakan package `http` untuk GET request. Response body berhasil di-decode (100 item). Skenario gagal (URL salah) ditangani dengan `throw Exception` dan `try-catch`, menampilkan `HTTP 404` di console tanpa crash.

### Tahap 3 — Model Dart
Menambahkan field `id` pada model `Course`. Dilakukan mapping di `Course.fromJson` (misal: `body` → `description`, dan `id` → `code` format `POST-{id}`). Data List JSON dikonversi menggunakan `.map((e) => Course.fromJson(e))`.

### Tahap 4 — Service Layer
Memindahkan akses HTTP ke `CourseApiService` dan menyuntikkannya ke `CourseRepositoryImpl`. File `course_service.dart` (pembaca asset JSON) dihapus. UI otomatis berubah menampilkan data API tanpa mengubah kode UI (bukti *separation of concerns*).

### Tahap 5 — Async State UI
Membuat widget reusable `ErrorView`. Merapikan urutan pengecekan: Loading → Error → Empty → Success. Tombol "Coba Lagi" berhasil memanggil `provider.refresh()`.

### Tahap 6 — HTTP POST
Implementasi `createCourse()` dengan payload JSON. Form dialog dibuat dengan validasi. Flag `isSaving` mencegah *double submit*. Setelah request berhasil, list di-refresh dan menampilkan SnackBar sukses.

### Tahap 7 — HTTP PUT/PATCH
Implementasi `updateCourse()`. `CourseFormDialog` dimodifikasi agar reusable untuk Create & Update. Field `code` dibuat `readOnly` karena dipakai sebagai kunci Favorites. Diterapkan *optimistic update* di Provider.

### Tahap 8 — HTTP DELETE
Implementasi `deleteCourse()`. Ditambahkan `AlertDialog` konfirmasi. `CourseProvider.removeCourse` juga membersihkan `code` dari `_favorites` agar tidak ada data yatim.

### Tahap 9 — Repository Pattern
Refactor arsitektur dengan *Dependency Inversion Principle*. Dibuat `abstract class CourseDataSource`. Repository bergantung pada kontrak, bukan implementasi. Mengubah sumber data hanya perlu 1 baris di DI.

### Tahap 10 — Supabase Client
Membuat project Supabase, menambahkan `supabase_flutter`, inisialisasi `Supabase.initialize()` di `main()`.

> **⚠️ Pelajaran Penting (Insiden Keamanan):** Awalnya URL dan anon key tersimpan langsung di source code (AppConfig) dan `.env` tidak sengaja ter-*commit* ke GitHub. Key tersebut saya **rotasi** di Supabase Dashboard, `.env` dihapus dari history Git menggunakan `git filter-repo`, dan sejak itu `.env` masuk `.gitignore`. URL & key kini dibaca via `flutter_dotenv` melalui `AppConfig`. Hanya `anon key` yang dipakai (bukan `service_role`), dan RLS diaktifkan sebagai lapisan keamanan utama.

### Tahap 11 — Database Schema
Membuat tabel `courses` (kolom: `id`, `code`, `title`, `credits`, `status`, `description`, `dosen`, `created_at`). Mengaktifkan RLS dan 4 policy. Melakukan *seeding* 5 data awal (MOB01-MOB05). Validasi `not null` terbukti bekerja.

### Tahap 12 — SELECT
Membuat `CourseSupabaseService.getCourses()` dengan `.from('courses').select().order('id')`. Mengganti sumber data di DI dari `CourseApiService` ke `CourseSupabaseService`. Berkat Repository Pattern, hanya 1 baris yang berubah.

### Tahap 13 — INSERT
Implementasi `createCourse()` dengan `.insert().select().single()` agar mendapat `id` otomatis dari database. Error handling `PostgrestException` (kode 23505 untuk duplicate code) menampilkan pesan ramah pengguna.

### Tahap 14 — UPDATE
Implementasi `updateCourse()` dengan `.update().eq('id', id)`. Sangat berhati-hati menyertakan `.eq()` agar tidak meng-update seluruh tabel. Field `code` tidak dikirim ke database karena *read-only*.

### Tahap 15 — DELETE
Implementasi `deleteCourse()` dengan `.delete().eq('id', id)`. Data terhapus permanen dari database. Favorites otomatis dibersihkan (tidak ada *orphan data*).

### Tahap 15.5 — FIX BUG
Audit menyeluruh dan perbaikan:

### Tahap 17 — Debugging, Network Failure & Security Check
Pada Tahap 17, saya melakukan pengujian menyeluruh terhadap 5 skenario error untuk memvalidasi ketahanan aplikasi (*robustness*).

- **Kasus A (HTTP 404/Endpoint Salah):** Aplikasi menampilkan `ErrorView` dengan pesan `SocketException`. Aplikasi tidak *crash*, dan setelah URL dikembalikan ke semula, data berhasil dimuat kembali.
- **Kasus B (Network Failure):** Saat internet dimatikan dan tombol Refresh ditekan, muncul `ErrorView`. Setelah internet dinyalakan dan tombol "Coba Lagi" ditekan, data muncul kembali.
- **Kasus C (JSON Mapping Error):** Saya sengaja memaksa tipe data yang salah (`status: 12345 as String`). Console menampilkan `TypeError`, namun aplikasi tidak *crash*, melainkan menampilkan `ErrorView`.
- **Kasus D (Supabase RLS/Permission):** Saya menghapus policy SELECT untuk sementara. Aplikasi menampilkan `PostgrestException` (permission denied). Setelah policy dikembalikan, data berhasil dimuat.
- **⚠️ Temuan Kritis Kasus E (Duplicate/Invalid Data):** Saat menguji input kode ganda, saya menemukan aplikasi berhasil membuat 2 course dengan kode yang sama (misal: dua `MOB01`). Hal ini terjadi karena saat *setup* tabel di Supabase (Tahap 11), saya lupa mengaktifkan *unique constraint* pada kolom `code`.

**Perbaikan Kasus E:** Saya segera menjalankan perintah SQL berikut di Supabase SQL Editor:
```sql
alter table courses add constraint courses_code_key unique (code);
```
Setelah *constraint* aktif, saya menguji ulang dan aplikasi kini berhasil menolak input kode ganda dengan `SnackBar` error: *"Gagal: Kode course 'MOB01' sudah digunakan."* (dari `PostgrestException` kode `23505`).

**Security Check:** Tidak ada `service_role` key di kode. `.env` masuk `.gitignore` dan tidak ter-*track* Git. RLS Supabase berfungsi sebagai lapisan keamanan backend.
